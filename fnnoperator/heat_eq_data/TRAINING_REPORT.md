# Training Report: Fourier Neural Operator for Heat Equation

## Executive Summary

This report provides a comprehensive technical overview of the training script (`train_fno.py`) that trains a Fourier Neural Operator (FNO) to solve the 1D heat equation. The model learns to map initial temperature distributions to final states through a neural operator framework, enabling rapid inference without solving the PDE numerically at inference time.

**Key Achievement**: The trained model can predict the solution of the heat equation at any time point given an initial condition, achieving resolution invariance and generalization to unseen initial conditions.

---

## 1. Problem Formulation

### 1.1 Physical Problem

The 1D heat equation is a parabolic partial differential equation:

$$\frac{\partial u}{\partial t} = \alpha \frac{\partial^2 u}{\partial x^2}$$

Where:
- $u(x,t)$ is the temperature at position $x$ and time $t$
- $\alpha$ is the thermal diffusivity coefficient
- Boundary conditions: $u(0,t) = u(L,t) = 0$ (Dirichlet boundary conditions)
- Domain: $x \in [0, L]$, $t \in [0, T]$

### 1.2 Neural Operator Learning Task

The model learns a mapping:
$$\mathcal{G}: u_0(x) \mapsto u_T(x)$$

Where:
- **Input**: Initial condition $u_0(x) = u(x, 0)$ - a function over spatial domain
- **Output**: Final state $u_T(x) = u(x, T)$ - solution at time $T$
- **Goal**: Learn operator $\mathcal{G}$ from data pairs $(u_0, u_T)$

This is fundamentally different from traditional PINNs (Physics-Informed Neural Networks) because:
- We learn the solution operator directly, not a function approximator
- The model generalizes to different initial conditions
- Resolution invariance allows evaluation at different grid resolutions

## 3. Model Architecture: Fourier Neural Operator (FNO)

### 3.1 Overview

FNO is a neural operator architecture that operates in the **Fourier domain**. Unlike traditional CNNs that work in spatial domain, FNO:
- Applies convolution in frequency domain (via FFT)
- Maintains resolution invariance
- Captures long-range dependencies efficiently

### 3.2 Architecture Components

#### 3.2.1 Lifting Layer
**Purpose**: Projects input function into higher-dimensional feature space

```
Input: (batch, in_channels=1, nx)
  ↓
Linear Projection + Positional Embedding
  ↓
Output: (batch, hidden_channels, nx)
```

**Configuration**:
- `lifting_channel_ratio = 2` → Lifting channels = `2 * hidden_channels`
- Adds positional encoding (grid coordinates) to input

#### 3.2.2 FNO Blocks (Core)
**Structure**: Stack of `n_layers` FNO blocks (default: 4)

Each FNO block consists of:

```
Input Features
  ↓
Spectral Convolution (Fourier domain)
  ├─→ FFT to frequency domain
  ├─→ Mode truncation (keep top n_modes frequencies)
  ├─→ Complex-valued multiplication
  └─→ IFFT back to spatial domain
  ↓
Channel-wise MLP (mixing channels)
  ↓
Activation (GELU)
  ↓
Skip Connection (linear projection)
  ↓
Output Features
```

**Key Parameters**:
- `n_modes = 16`: Number of Fourier modes to retain (must be < nx/2 due to Nyquist)
  - Lower modes capture large-scale patterns
  - Higher modes capture fine details
  - Truncation acts as implicit regularization
- `hidden_channels = 64`: Width of network (feature dimension)
- `n_layers = 4`: Depth of network

#### 3.2.3 Spectral Convolution Details

For 1D FNO with spatial resolution $N$:

1. **Forward FFT**: Transform to frequency domain
   $$X[k] = \sum_{n=0}^{N-1} x[n] e^{-i 2\pi k n / N}$$

2. **Mode Truncation**: Keep only low-frequency modes
   - Retain modes: $k \in \{0, 1, ..., n_{modes}-1\}$
   - Discard high-frequency modes (acts as low-pass filter)

3. **Spectral Multiplication**: Complex-valued convolution
   $$Y[k] = W[k] \cdot X[k]$$
   Where $W[k]$ are learnable complex weights

4. **Inverse FFT**: Transform back to spatial domain
   $$y[n] = \frac{1}{N} \sum_{k=0}^{N-1} Y[k] e^{i 2\pi k n / N}$$

**Why this works**:
- Efficient: Convolution in frequency domain is element-wise multiplication
- Captures global dependencies without large receptive fields
- Resolution invariant: Works at any grid resolution

#### 3.2.4 Projection Layer

**Purpose**: Maps features back to output space

```
Hidden Features (batch, hidden_channels, nx)
  ↓
Linear Projection
  ↓
Output (batch, out_channels=1, nx)
```

**Configuration**:
- `projection_channel_ratio = 2` → Projection channels = `2 * hidden_channels`

### 3.3 Model Instantiation

```python
model = FNO(
    n_modes=(16,),           # 1D: single spatial dimension
    in_channels=1,            # Initial condition (1 channel)
    out_channels=1,           # Final state (1 channel)
    hidden_channels=64,       # Network width
    n_layers=4,               # Number of FNO blocks
    projection_channel_ratio=2,
    lifting_channel_ratio=2,
)
```

**Model Size**: ~345,665 parameters (for default config)

## 4. Data Processing Pipeline

### 4.1 Data Loaders

Three DataLoaders are created:
1. **TrainLoader**: Batches training data, shuffles samples
2. **TestLoader**: Batches test data, no shuffling
3. **ValLoader**: Batches validation data, no shuffling

**Configuration**:
- `batch_size = 32`: Training batch size
- `shuffle = True`: Only for training (improves convergence)
- `pin_memory = True`: If CUDA available (faster GPU transfer)

### 4.2 Normalization (DataProcessor)

#### 4.2.1 UnitGaussianNormalizer

**Purpose**: Normalize data to zero mean and unit variance for stable training

**Implementation**:
```python
normalizer = UnitGaussianNormalizer(dim=[0, 2])
normalizer.fit(training_data)  # Compute mean and std

# Transform: (x - mean) / (std + eps)
normalized = normalizer.transform(data)
# Inverse: normalized * std + mean
original = normalizer.inverse_transform(normalized)
```

**Normalization Strategy**:
- `dim=[0, 2]`: Normalize over **batch** dimension (0) and **spatial** dimension (2)
- Preserves channel-wise statistics
- For shape `(batch, channels, spatial)`: computes mean/std over batch and spatial, per channel

**Why this matters**:
- Inputs: Initial conditions have varying scales → normalization stabilizes learning
- Outputs: Final states are normalized during training, denormalized for evaluation
- Prevents gradient explosion/vanishing

#### 4.2.2 DefaultDataProcessor

**Workflow**:

1. **Preprocessing** (before model forward pass):
   ```python
   data_dict = {"x": input, "y": target}
   data_dict = processor.preprocess(data_dict)
   # → Normalizes 'x' (input) and 'y' (target) if training mode
   # → Moves tensors to device (CPU/GPU)
   ```

2. **Postprocessing** (after model prediction):
   ```python
   pred = model(data_dict["x"])
   pred, data_dict = processor.postprocess(pred, data_dict)
   # → Denormalizes 'pred' if evaluation mode
   # → Keeps normalized for loss computation during training
   ```

**Important**: 
- **During training**: Loss computed on normalized data (more stable gradients)
- **During evaluation**: Metrics computed on denormalized data (actual physical values)

## 5. Training Loop Architecture

### 5.1 High-Level Flow

```
Initialize Model, Optimizer, Scheduler, Loss Functions
  ↓
For each epoch:
  ├─→ Train Phase:
  │   ├─→ For each batch:
  │   │   ├─→ Load batch
  │   │   ├─→ Preprocess (normalize, move to device)
  │   │   ├─→ Forward pass: pred = model(x)
  │   │   ├─→ Postprocess (keep normalized for loss)
  │   │   ├─→ Compute loss: loss = loss_fn(pred, y)
  │   │   ├─→ Backward pass: loss.backward()
  │   │   └─→ Optimizer step: optimizer.step()
  │   └─→ Update learning rate: scheduler.step()
  │
  └─→ Evaluation Phase (every eval_interval epochs):
      ├─→ Set model to eval mode
      ├─→ For each test batch:
      │   ├─→ Forward pass (no gradients)
      │   ├─→ Postprocess (denormalize)
      │   └─→ Compute evaluation metrics
      └─→ Log metrics, save checkpoints
```

### 5.2 Trainer Class (neuralop.training.Trainer)

The `Trainer` class encapsulates the training logic:

#### 5.2.1 Initialization

```python
trainer = Trainer(
    model=model,
    n_epochs=50,
    device="cpu" or "cuda",
    data_processor=data_processor,
    wandb_log=False,
    eval_interval=5,        # Evaluate every 5 epochs
    use_distributed=False,
    verbose=True,
)
```

#### 5.2.2 Training Method

```python
trainer.train(
    train_loader=train_loader,
    test_loaders={"test": test_loader},
    optimizer=optimizer,
    scheduler=scheduler,
    training_loss=h1_loss,
    eval_losses={"h1": h1_loss, "l2": l2_loss},
    save_every=5,           # Save checkpoint every 5 epochs
    save_dir="checkpoints", # Checkpoint directory
)
```

#### 5.2.3 Epoch Training (train_one_epoch)

For each training epoch:

1. **Set model to training mode**:
   ```python
   model.train()
   data_processor.train()  # Enable normalization for targets
   ```

2. **Iterate over batches**:
   ```python
   for batch in train_loader:
       # Forward pass
       sample = data_processor.preprocess(sample)  # Normalize
       pred = model(sample["x"])
       pred, sample = data_processor.postprocess(pred, sample)  # Keep normalized
       
       # Compute loss
       loss = training_loss(pred, sample["y"])
       
       # Backward pass
       loss.backward()
       
       # Optimizer step
       optimizer.step()
       optimizer.zero_grad()
   ```

3. **Update learning rate**:
   ```python
   scheduler.step()  # Cosine annealing or ReduceLROnPlateau
   ```

4. **Compute epoch metrics**:
   - Average training loss
   - Learning rate

#### 5.2.4 Evaluation (evaluate)

Every `eval_interval` epochs:

1. **Set model to evaluation mode**:
   ```python
   model.eval()
   data_processor.eval()  # Denormalize outputs for metrics
   ```

2. **Iterate over test batches** (no gradients):
   ```python
   with torch.no_grad():
       for batch in test_loader:
           sample = data_processor.preprocess(sample)
           pred = model(sample["x"])
           pred, sample = data_processor.postprocess(pred, sample)  # Denormalize
           
           # Compute evaluation losses
           for loss_name, loss_fn in eval_losses.items():
               metric = loss_fn(pred, sample["y"])
               metrics[f"test_{loss_name}"] = metric
   ```

3. **Return metrics dictionary**:
   ```python
   {
       "test_h1": float,
       "test_l2": float,
       ...
   }
   ```

## 6. Loss Functions

### 6.1 H1 Loss (Training Loss)

**Mathematical Definition**:

$$L_{H^1}(u, \hat{u}) = \|u - \hat{u}\|_{L^2} + \|\nabla u - \nabla \hat{u}\|_{L^2}$$

Where:
- First term: $L^2$ norm of function values
- Second term: $L^2$ norm of gradients (spatial derivatives)

**For 1D discrete data**:
$$L_{H^1} = \frac{1}{N} \sum_{i=1}^{N} |u_i - \hat{u}_i|^2 + \frac{1}{N} \sum_{i=1}^{N-1} \left|\frac{u_{i+1} - u_i}{\Delta x} - \frac{\hat{u}_{i+1} - \hat{u}_i}{\Delta x}\right|^2$$

**Why H1 Loss?**:
- **PDE-informed**: Penalizes both function values and derivatives
- **Better gradient flow**: Encourages smooth predictions
- **Physical relevance**: Heat equation is second-order (involves second derivatives)
- **Improved generalization**: Prevents overfitting to training data

**Implementation**:
```python
h1_loss = H1Loss(d=1)  # d=1 for 1D spatial domain
loss = h1_loss(pred, target)  # pred, target shape: (batch, channels, nx)
```

### 6.2 L2 Loss (Evaluation Metric)

**Mathematical Definition**:

$$L_{L^2}(u, \hat{u}) = \|u - \hat{u}\|_{L^2} = \frac{1}{N} \sum_{i=1}^{N} |u_i - \hat{u}_i|^2$$

**Usage**: 
- Evaluation metric (not used for training)
- Interpretable: Direct measure of pointwise error
- Standard metric for regression tasks

**Implementation**:
```python
l2_loss = LpLoss(d=1, p=2)  # L^p loss with p=2, d=1 (1D)
metric = l2_loss(pred, target)
```

### 6.3 Loss Computation Details

**Shape Requirements**:
- Input tensors: `(batch_size, channels, spatial_dim)`
- For 1D: `(batch_size, 1, nx)`
- Loss computes per-sample, then averages over batch

**Normalization Context**:
- During training: Loss computed on **normalized** data
- During evaluation: Loss computed on **denormalized** data (physical units)

## 7. Optimization Strategy

### 7.1 Optimizer: AdamW

**Configuration**:
```python
optimizer = AdamW(
    model.parameters(),
    lr=1e-3,              # Learning rate
    weight_decay=1e-4,    # L2 regularization
)
```

**AdamW Details**:
- **Adaptive learning rates**: Per-parameter learning rates based on gradient history
- **Momentum**: Uses exponential moving averages of gradients (first moment) and squared gradients (second moment)
- **Weight decay**: Decoupled from gradient-based updates (unlike standard Adam)
- **Benefits**: Robust to learning rate choice, good for non-convex optimization

### 7.2 Learning Rate Schedule: Cosine Annealing

**Configuration**:
```python
scheduler = torch.optim.lr_scheduler.CosineAnnealingLR(
    optimizer,
    T_max=n_epochs,  # Total number of epochs
)
```

**Learning Rate Schedule**:

$$lr(t) = lr_{min} + (lr_{max} - lr_{min}) \cdot \frac{1 + \cos(\pi t / T_{max})}{2}$$

Where:
- $t$: Current epoch
- $T_{max}$: Total epochs
- $lr_{max}$: Initial learning rate (1e-3)
- $lr_{min}$: Minimum learning rate (0, by default)

**Benefits**:
- **Smooth decay**: Gradual reduction helps fine-tuning
- **Convergence**: Ends near zero learning rate for stability
- **No plateau detection needed**: Predictable schedule

### 7.3 Gradient Flow

**Backward Pass**:
```python
loss.backward()  # Computes gradients via automatic differentiation
```

**Gradient Clipping**: Not explicitly used, but can be added if needed:
```python
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
```

**Optimizer Step**:
```python
optimizer.step()      # Update parameters using gradients
optimizer.zero_grad() # Clear gradients for next iteration
```

## 11. Key Design Decisions and Rationale

### 11.1 Why FNO for Heat Equation?

- **Resolution invariance**: Can evaluate at any grid resolution
- **Global dependencies**: Fourier domain captures long-range correlations
- **Efficiency**: Spectral convolution is fast via FFT
- **Operator learning**: Learns solution operator, not just function approximation

### 11.2 Why H1 Loss?

- **PDE-aware**: Penalizes derivatives (relevant for heat equation)
- **Smoothness**: Encourages physically realistic solutions
- **Gradient information**: Captures solution structure better than L2 alone

### 11.3 Why Normalization?

- **Stability**: Prevents gradient explosion/vanishing
- **Convergence**: Faster training with normalized data
- **Generalization**: Works across different initial condition scales

### 11.4 Why Cosine Annealing?

- **Fine-tuning**: Gradual learning rate decay helps convergence
- **Predictable**: No need for plateau detection
- **Standard practice**: Common in neural operator training

### 11.5 Why Separate Train/Test/Val Splits?

- **Generalization assessment**: Test set never seen during training
- **Hyperparameter tuning**: Validation set for model selection
- **Overfitting detection**: Monitor test loss vs training loss

## 13. Performance Considerations

### 13.1 Computational Complexity

**FNO Forward Pass**:
- FFT: $O(N \log N)$ per layer
- Spectral convolution: $O(N \cdot n_{modes})$ per layer
- Overall: $O(L \cdot N \log N)$ where $L$ = number of layers, $N$ = spatial resolution

**Training**:
- Per batch: Forward + Backward (2x forward cost)
- Per epoch: Number of batches × batch cost
- Total: Epochs × batches × batch cost

### 13.2 Memory Requirements

- **Model parameters**: ~345K parameters × 4 bytes ≈ 1.4 MB
- **Activations**: Batch size × hidden_channels × nx × 4 bytes
- **Gradients**: Same as parameters (for backward pass)

### 13.3 GPU vs CPU

- **GPU**: 10-100x faster training (depending on batch size and model size)
- **CPU**: More accessible, sufficient for small models and datasets
- **Mixed precision**: Can be enabled for 2x speedup on modern GPUs

## 14. Troubleshooting and Common Issues

### 14.1 Training Instabilities

**Symptom**: Loss becomes NaN or explodes

**Solutions**:
- Reduce learning rate (try 1e-4)
- Add gradient clipping
- Check data normalization
- Verify initial conditions are reasonable

### 14.2 Overfitting

**Symptom**: Training loss decreases but test loss plateaus/increases

**Solutions**:
- Increase weight decay
- Reduce model capacity (hidden_channels, n_layers)
- Add more training data
- Use dropout (if available in FNO blocks)

### 14.3 Underfitting

**Symptom**: Both training and test loss high, not decreasing

**Solutions**:
- Increase model capacity
- Reduce weight decay
- Increase training epochs
- Check data preprocessing

### 14.4 Slow Convergence

**Symptom**: Loss decreases very slowly

**Solutions**:
- Increase learning rate (carefully)
- Check learning rate schedule
- Verify optimizer configuration
- Check data normalization
